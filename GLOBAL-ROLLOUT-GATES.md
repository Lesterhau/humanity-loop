# Worldwide rollout gates — evidence before expansion

**As of 2026-11-18 UTC:** the last production intake read reported **zero registered contributor nodes and zero MCP node submissions**. Public visibility, a signed Waystation invitation, a protocol handshake, and owner-run simulated models do NOT satisfy an outside contribution.

This is a **sequence of release gates**, not authorization for simultaneous worldwide recruitment, recurring execution, paid inference, private-account access, or higher-risk agent actions.

## Gate 0 → 1: Prove the full independent loop

- Receive one adult non-owner's explicit consent, verify the actual MCP tool list and data retention warning, register only a Tier-0 node, claim one unexpired public-web task, submit source-backed observations into quarantine, and obtain a **separate reviewer decision**.
- Log separately: invitation seen, contacted, connected, registered, claimed, submitted, independently reviewed, accepted or rejected, and **real external-benefit outcome**. Do not conflate stages.
- Failure/idle/unsupported host is a valid trial outcome; revise instructions without pretending adoption.
- Current blocked dependencies: [independent pilot issue #33](https://github.com/Lesterhau/humanity-loop/issues/33), [retention/deletion issue #96](https://github.com/Lesterhau/humanity-loop/issues/96), [branch-protection #68](https://github.com/Lesterhau/humanity-loop/issues/68).

## Gate 1 → 5: Make onboarding repeatable

- Five independent adult operators, across at least two genuinely distinct AI hosts. These are **targets, not achievements**.
- Test that revoked tokens stop access, no duplicate task lease can be claimed, public source evidence is real, errors are visible, and no leaked token reaches a public GitHub comment.
- Provide readable accessibility, low-bandwidth onboarding, screen-reader checks and one translated pilot packet validated by a qualified fluent reviewer; do not rely on machine translation alone for consent/legal language.
- Add notification/triage SLA measurement, not simply scheduled cron "success".

## Gate 5 → 25: Multiregional pilot

- At least two countries and multiple time zones, chosen where adult participants and source reviewers have opted in—not arbitrary outreach.
- Regional public information sources require jurisdiction-specific relevance and dated authoritative links. Do not automatically generalize U.S. public-benefit rules to other regions.
- Separate human-review competence by topic and language. Maintain transparent refusal/escalation for medical, legal, benefit eligibility, political persuasion and any minors' data.
- Validate privacy/retention, cross-border transfers and applicable regional rules before collecting participants' identifiers. Never announce legal compliance without qualified review.
- Make tool/client status visible in the participant's own language and offer pause/revoke without forcing a new account.

## Gate 25 → 100 → 1,000: Responsible capacity

- No active-active Foundry workers. Use **one canonical claim/lease authority**, rate limits, idempotency keys, human review and public-safe evidence receipts.
- Evaluate donated local open-weight model capacity and hosted inference separately; no silent paid key fallback, unbounded GPU usage or volunteer bill. Model count is not independent evidence validation.
- Explicit quotas by source, tenant, model and region, with kill switch and data-deletion workflow tested. Monitor actual cost per **independently accepted useful contribution** and cost per verified downstream correction.
- Publish a defensible privacy and incident-response contact path, reproducible reviewer policy, audit retention windows and appeal mechanism.
- Track geographic coverage by volunteered region/language (no unnecessary sensitive locations), acceptance quality and failure rates rather than raw page views.
- Security: protect governance/automation control files in main, use a separate least-privileged agent writer, and preserve GitHub detector workflows before toggling branch protection.

## Distribution and measurement

- Default to **opt-in** invitations, documented machine-readable signals and support from existing cooperating operators.
- AgentBeacon and Waystation are not universal agent push systems; agents need an opted-in discovery channel and a response route that is actually monitored.
- For each lane report: contacted (with consent), discovery → tool handshake → register → claim → submit → review → sourced real benefit; median response time, 95th-percentile delay, model-run/provider costs and reviewer capacity.
- Keep Humanity Loop's public-interest evidence and RL Perspectives' separate commercial beacon venture legally and operationally distinct.

## Foundry infrastructure choices

| Component | Current recommended choice | Why and limits |
| --- | --- | --- |
| State and leases | Existing Supabase hl_control | One authority; preserve security review and free-tier inactivity constraints |
| CI/manual no-model compute | Existing public GitHub Actions | Free standard public-repo CI within policy; not an always-on GPU worker |
| Optional local open-weight inference | Ollama / llama.cpp | No AppDeploy credits; uses operator hardware/electricity, each model has its own license |
| Future workflow framework | LangGraph or Pydantic AI | Both MIT-licensed; add only if existing FoundryControlPlane becomes insufficient |
| Global lightweight edge | Cloudflare Workers | Free request cap; separate Workers AI quotas and restricted models; requires account integration and hard-stop testing |
| Existing status mirror | Render static service | Read-only web/status page, NOT a model runtime |
| Avoid as automatic first choice | Replit free app / GPU server | Demo quota/expiry, no dependable worldwide always-on free model service |
| Hugging Face Spaces | Static docs or gated ZeroGPU experiment | Static Spaces free; CPU/Docker compute may require a paid plan; personal ZeroGPU limited |
| AppDeploy Foundry Alpha | Paused | Balance below owner-protected 350-credit reserve; do not autoenable after reset |

## Mature G5 scale and recognition (owner target, November 25)

Extend checkpoints to 5,000 and 20,000 active independent nodes, not raw registrations. Count distinct consenting operators, meaningful accepted work in rolling 28 days, retention, unique verified outcomes, actual monthly recurring donors (target 1,000), net receipts and review capacity. No assumed exponential growth; evaluate observed longitudinal growth. G5-A retains the operational viability thresholds; G5-B requires measured mature scale and operational Impact Passport, actual institutional recognition and transparent authorized MOTHER engagement. Portable user-shared credentials and formal platform partnership (LinkedIn or appropriate equivalent) are separate milestones. No partner agreement, issued credential, funding, outreach or release is implied. First step: one genuine accepted contribution, separate review and optional private consented Passport record.
