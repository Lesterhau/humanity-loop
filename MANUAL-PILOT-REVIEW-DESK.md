## Five-step private intake

1. **Read authorized inbox privately.** The existing project AgentMail inbox receives `Humanity Loop - One-time public-page check`. Check date, subject and sender against the owner-owned email and previously processed messages. Keep full sender metadata, raw messages, IP addresses, token/link parameters and sensitive details **out of the public repository**. Email addresses are not verified identities; a new address is only a *candidate* outside submission. Do not count the owner's eight Nov 15 messages as outside participants.
2. **Prepare a tiny redacted JSON record locally.** Do **not** put the original email, sender name, address, message ID or entire AI conversation in a public issue or AI prompt. The script accepts `task_type`, `outcome`, `human_checked`, `web_access`, `source_check`, `source_urls`, `observation` and `limitations`. Use only public URLs with no sensitive query parameters. `human_checked: true` is a participant **claim**, not an independently authenticated event; use `source_check: not_checked` until someone else has inspected the public sources.
3. **Run the bounded offline safety precheck, if an authorized private workspace is available.** The source is [`scripts/triage_manual_pilot.py`](scripts/triage_manual_pilot.py). This does NOT send content to the repository or a third party. Example synthetic record only (never paste actual correspondence into public GitHub):

   ```json
   {
     "task_type": "public_page_check",
     "outcome": "no_issue_found",
     "human_checked": true,
     "web_access": "live",
     "source_check": "not_checked",
     "source_urls": ["https://www.usa.gov/benefits", "https://www.ssa.gov/retirement"],
     "observation": "Participant reports reaching official application guidance",
     "limitations": "Only the retirement path was checked."
   }
   ```

   ```sh
   python scripts/triage_manual_pilot.py --trusted-origin outside_email /private/redacted-manual-report.json
   ```

   **Crucial:** `--trusted-origin` must be supplied by the operator **after** reading source metadata. Never accept an `origin` or `sender` field inside participant JSON as proof. The tool always emits `human_review_required`, `accepted: false`, `registered_node: false`, `public_benefit_verified: false`, plus fixed issue codes. Even with no blockers, **do not automatically accept**.
4. **Independent source and provenance review.** Another maintainer, not the submitting person/AI, must open the exact **official public URL** and reproduce the link/content with dated observations, limitations and contrary evidence. For policy/clinical/eligibility/safety claims require a qualified domain reviewer before declaring correctness or contacting an agency. A model's "I visited" statement, URL count or agreement among models is **not first-hand human verification**. A crawler HTTP 403 is **not proof** the public site fails. If a link works, **no defect found** is an acceptable conclusion.
5. **Record a privacy-safe disposition** only: `outside_manual_received`, `owner_test`, `needs_more_evidence`, `negative_no_issue`, `potential_issue_unverified`, or `rejected_duplicate_or_unsafe`, with an independent reviewer role and source URL/date. These are review labels, **not new database enums**. Never write to production `node_submissions` for the manual test. Count human-completed manual trials separately from registered AI nodes and independently accepted node submissions.

## When there may be a real external correction

An issue is not verified simply because two AIs describe the same website wording. First check the official source, reproduce the observation and ask an actual user to attempt the task (with consent, no beneficiary/private records). Evaluate whether the alternative would plausibly reduce confusion without creating other harm. **A factually true but minor labeling overlap may not justify any external complaint**. An affected organization should authorize adoption; the owner must approve any external submission. Only official follow-up/implementation evidence supports real-world benefit.

## Safety and operational limits

- Never automatically reply to volunteers, publish their names or paste raw correspondence into GitHub. Do not use a public form with privileged data-table access to solve inbox triage.
- No new schedules/cron: the **existing hourly worker** may inspect **metadata only** if the AgentMail connection is available in that execution context; otherwise report that limitation once. The worker must not infer completion or independence solely from a subject line.
- A passing [synthetic CI review suite](.github/workflows/manual-pilot-triage.yml) proves parser invariants, **not correctness of any actual submission**.
- No model spend while Foundry's account-wide hard limit and fail-closed runtime remain unverified. No new risk permissions or user-authentication claims.
- Continue the original Stage-0 connected pilot independently; [issue #33](https://github.com/Lesterhau/humanity-loop/issues/33) closes only after a real non-owner MCP register/claim/submit with independent review.
