# Humanity Loop — website maintenance and public trust

**Owner direction Nov 8, 2026:** Website maintenance is a standing operational duty even while Foundry and external impact work scale. Public availability, safety, and accurate outcomes take precedence over vanity metrics.

## Keep the basic public service functional
- Homepage /, /join, /api/mcp read methods, project protocol and independent documentation links: uptime, navigation, working links, accessibility (mobile/keyboard/screen reader), language and clarity.
- Registration: default Tier-0, no accidental escalation. A real outside-client consented register -> checkin -> claim -> submit -> quarantine -> reviewer acceptance remains the adoption gate. Test pause and permanent revoke without leaking tokens.
- Site presents **truthful counts** for registered/active nodes, quarantined/accepted submissions and verified adopted outcomes. No invented impact badge, fake partner adoption or implied persistent remote-AI execution.
- Privacy: no private mail, raw node token, personal beneficiary details or host secret in public build, log, URLs, source, SEO metadata or analytics.
- Security: cross-origin and input limits, no unreviewed external text promoted into automation instructions, repository main branch protection/rulesets and least-privileged writer identity. See issue #33, #66.
- Platform: check Vercel Hobby/LLC commercial eligibility in #57, build status, quotas, 5xx/4xx, and free-tier limits; choose a reversible, permissioned hosting path before migration. No plan upgrade or unbounded build cadence.
- Content: present genuine implemented outcomes, source age, independent review and correction route. Page corrections are service hygiene, not standalone public impact.

## Cadence and ownership
**At each existing hourly worker run:** one quick status/exception triage when needed (not repeated network probes if nothing changed); if no new evidence or alert, continue non-audit external-benefit work.

**Weekly (within existing permitted cadence, no new job):** sample homepage, /join, MCP read endpoint, accessibility/privacy, last production build receipt, free-plan limits and task-expiry risk. Issue a durable evidence receipt only for material changes or failures. Do not create synthetic traffic, content or registered users.

**Before expanding beta or publishing outcomes:** independent review that actual frontend registration and edge gateway enforce the same Tier-0 policy; a real contributor flow; correct adoption/protocol disclosures; no unsafe social/account autonomy.

## Explicit non-goals until approved
No new automated monitor, paid provider subscription, outbound site promotion, new model inference, private-data crawling or production migrations solely to satisfy a dashboard. MOTHER's eventual paid X verification is handled by MOTHER.md's readiness/approval gates, not website runtime.
