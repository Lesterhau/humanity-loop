Existing subscriptions paid by individual users are not free credits for Humanity Loop; neither Claude Pro nor Perplexity Pro creates transferable API allowance. Do not promise zero incremental cost if a separately billed service is in use.
2. **Native Foundry cron OFF** (`cron.json=[]`) until explicitly approved after actual failure-path, budget, canonical task approval/lease and independent Tier-0 artifact acceptance. The existing Humanity Loop Hourly Worker stays on its current schedule; the separate ChatGPT Foundry Recovery automation remains disabled. Never add a second runner or revive a detector where GitHub already owns the same work without verifying coverage and turning the duplicate off.
3. **This Free cycle:** maintain a target **350-credit reserve** out of the current 390.41 remaining for existing operations, incidental usage and unknown hosting costs; maximum **40 credits total** for any additional **explicitly owner-consented** Foundry manual acceptance work before the November 26 reset, and less if balance declines. Default **zero automatic AI work**. A manual run may proceed only after verifying *fresh* daily, weekly and monthly dashboard headroom and a task-level hard bound; **do not interpret the 40-credit policy as AppDeploy-enforced spend limit**. If it cannot be enforced with token/call accounting and fail-closed controls, do not start a model loop. If projected non-Foundry operation exceeds the reserve, postpone even the manual probe.
4. **Initial new Free cycle (after reset):** hold Foundry to **at most 100 credits/month**, no more than **one owner-reviewed manual task/week**, each at most **25 estimated model credits**, until **seven days of per-app usage and host cost** establish a stable non-Foundry baseline. These are upper envelopes, not promised entitlements. Never extrapolate the 1,000 monthly quota to every day; check each of the three concurrent provider caps and any plan change.
5. **Only increase quota after measurements:** calculate `free_model_headroom = min(verified_monthly_after_forecast_and_reserve, verified_weekly_headroom, verified_daily_headroom)`; use zero when any factor is unknown or inadequate. Reserve baseline hosting, six existing app operations, and an incident cushion first. Review source parity and retire *redundant* native jobs only after verified handover, protecting Evidence Integrity's distinct coverage. Prefer deterministic GitHub Actions, public-source research and owner/volunteer-supplied inference already covered by their host plans over AppDeploy built-in AI where practical and permitted.
6. **Per-execution control contract (not yet fully implemented):** human-approved bounded Tier-0 staging task; verified identity; unique idempotency/lease; fixed model call count (target <=3), fixed per-call and aggregate combined input/output token budgets, no model self-retry, no tools or external writes without separate approval, emergency stop, one persisted receipt per stage, failure/non-2xx visible. Test prompt growth/input accounting and after-run **actual** credit delta. Output cap alone is NOT a hard credit cap; reject if provider cannot guarantee a ceiling.
7. **Funding gate:** donations/support through RL Perspectives, LLC are not tax-deductible charity contributions. Do not treat pledges or gross Stripe payments as available capacity. Owner must authorize a documented funded operating budget, with verified net cleared funds, reserve and paid-service risk before upgrading. Do not automatically buy capacity even if donations arrive.

## External contributor nodes: whose usage is it?

- An independent Claude, ChatGPT, Perplexity or other MCP host typically uses **the participant's own subscription quota / credits / metered API** for model inference. Merely connecting Humanity Loop's **remote MCP** does not transfer those credits to the project or make agents run autonomously. Some hosts permit free usage; some have rate limits; API/paid runtimes can cost participants money.
- Humanity Loop can still incur **its own** Vercel/Supabase/API/hosting/database cost when nodes call the public MCP and submit tasks. They do **not automatically consume the owner's AppDeploy AI credits** unless Foundry/AppDeploy services are involved.
- Default onboarding: **one explicitly consented Tier-0 manual task, zero background tasks, no contributor API-key upload, no auto-top-ups, no guaranteed badges or earnings**, permissioned revoke/pause. Before approving a recurring task, show the host, frequency, expected model/tool cost, whose allowance is used, a cap/stop behavior, and a lower-frequency/no-payment path. A free chat plan is not an unlimited server worker.
- Do not pressure volunteers to absorb unpredictable compute or privacy risk for a for-profit LLC. Preserve genuine human consent, independent review and separate AI-work vs human-hours accounting.
